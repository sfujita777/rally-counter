# 連続ラリーカウンター — 本番一式（PHASE 1）

四国フレスコボール協会の「連続ラリーカウンター」本番版。静的HTML1枚（`index.html`）＋
中央台帳（Google Apps Script `gas.gs`）で、**各地の端末から記録 → 中央に集約 → 大画面で常時ランキング**を実現する。

思想の正本＝[[../../../concepts/スポットライトの民主化-連続ラリーカウンター]]
設計の正本＝[[../連続ラリーカウンター-本格制作仕様]]

---

## ファイル
| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体。`?mode=count`＝カウンター／`?mode=board`＝ランキング大画面／無指定＝入口 |
| `gas.gs` | 中央台帳。スプレッドシートにバインドしWeb App公開（doGet=一覧・追記／JSONP） |

通信は **JSONP**（script タグ）。GitHub Pages など別ドメインの静的ページから GAS を叩くと
`fetch` はCORSで弾かれるため、CORSの要らない JSONP を採用している（読み込みも書き込みも同方式）。

## セットアップ手順

### ① 中央台帳（GAS）をデプロイ ＊しかりの手作業
1. 記録用スプレッドシートを開く（既存フォルダのシートを流用でOK）
2. 「拡張機能 → Apps Script」を開く
3. `gas.gs` の中身を全部貼り付けて保存
4. 「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
5. 発行された `https://script.google.com/macros/s/XXXX/exec` をコピー
   → 初回は承認ダイアログが出る（自分のGoogleアカウントで許可）
   - ※更新時は「デプロイを管理 → 編集 → 新バージョン」でURLを変えずに差し替え

### ② アプリにGAS URLを設定
- `index.html` 先頭の `CONFIG.GAS_URL` に ① の `/exec` URL を貼る
- （貼らずに動作確認したいときは `?api=<exec URL>` をURL末尾に付けて上書きも可）

### ③ GitHub Pages に公開 ＊しかりの手作業
- `gh` CLI は未導入のため、当面は **GitHub Web UI** で：
  1. 新規リポジトリ作成（例：`rally-counter`／Public）
  2. `index.html` をアップロード（ドラッグ＆ドロップ → Commit）
  3. Settings → Pages → Branch：`main` / `/root` → Save
  4. 数分後 `https://sfujita777.github.io/rally-counter/` が公開される
- 公開後URL：記録＝`…/?mode=count`、大画面＝`…/?mode=board`

## セキュリティ（承認制）＊2026-11-23 藤田確定
この構成は「誰でも書ける公開エンドポイント」になるため、**承認制**で守る。
- **board（ランキング閲覧）＝誰でも公開**。実名ペア名が出る前提。
- **count（記録送信）＝承認制**。送信は全部まず **承認=FALSE** で中央シートに溜まる。
  代表がシートの **「承認」列にチェック** を入れた記録だけが board に出る。
  → 立会ナシの「公式・99999回」等を捏造しても、承認しなければ表に出ない＝**偽装が無意味化**。
- **GAS側で上限チェック**：連続回数 1〜3000／文字数40字／空・異常値は拒否。
- 表示系のXSSは出力エスケープ済み。
- 本格認証（Googleサインイン必須化など）は**この規模では過剰**として入れていない。
  被害は「未承認シートへの落書き」に限定され、情報流出や他データ破壊は起きない。

### 代表の日々の運用
1. シートの「承認」列（チェックボックス）を、正しい記録だけONにする → ランキングに反映。
2. いたずら/間違いはチェックしない or 行を削除。
3. 初回だけ Apps Script で `setup()` を実行するとヘッダと承認列の体裁が整う。

## 使い方（現場）
- **記録端末（スマホ）**：`?mode=count`。ペア名・部門・立会代表・制限時間を選び「スタート」→
  落とさず続いたらタップ。10本ごとに音＋読み上げで沸く。時間切れ or 「ストップ＆記録」で保存＝中央台帳へ自動送信。
  - 電波が切れても端末に保存され、復帰後に自動再送（「未送信 N件」表示）。
  - Space/Enterキーや一部のBluetoothリモコンのボタンでもカウント可。
- **大画面**：`?mode=board`。公式のみ・上位10、総合＋部門タブを自動ローテーション、15秒ごと自動更新。

## 設定（`index.html` の `CONFIG`）
- `DIVISIONS` … **部門（★暫定）**。四国協会の正式な部門が決まったらここを編集。
- `WITNESSES` … 立会代表。`official:true` が公式記録の立会資格。
- `DURATIONS` / `BOARD_REFRESH_MS` / `BOARD_ROTATE_MS` / `BOARD_TOP_N` … 時間・更新間隔・表示件数。

## 記録のデータ構造
1記録 ＝ **選手ごとにクラブ＋名前**（ペアはクラブをまたいでOK）× カテゴリ × 時間 × 連続回数。
- 所属クラブ：SFC（香川）／KFC（高知）／UFC（徳島）／SNFC（愛媛）
- カテゴリ：男子／女子／ミックス／キッズ
- 時間：1〜5分
- クロスクラブのペア（例：UFC多田 ／ SFC藤田）は、**クラブ別集計で両クラブの取り組みとしてカウント**。

### シート列
`日時 ｜ クラブ1 ｜ 名前1 ｜ クラブ2 ｜ 名前2 ｜ カテゴリ ｜ 時間(分) ｜ 連続回数 ｜ 立会代表 ｜ 区分(公式/参考) ｜ 承認(TRUE/FALSE)`
※「承認」はチェックボックス。**ONの行だけがランキング（board）に出る**。

## ランキング（board）の見え方
- タブ：**総合／男子／女子／ミックス／キッズ／クラブ別**（自動ローテーション）
- 行：順位・名前（2人は「多田 ／ 藤田」）・所属クラブ（「UFC ／ SFC」）・カテゴリ・時間・連続回数
- クラブ別：各クラブの **参加人数・記録数・最高回数**（＝取り組み状況）

## PHASE 1 の未確定・要確認
- **SNFC（愛媛）の立会代表名**が未確定（現状「SNFC 代表（要確認）」）。名前が決まったら CONFIG.WITNESSES を更新。
- **時間（1〜5分）を同じランキングで並べてよいか** … 5分は1分より回数が伸びやすい。現状は「総合1本＋時間を列表示」。時間別のランキングに分けたい場合は対応可。
- GitHub Pages 公開作業（リポジトリ作成〜Pages有効化）は人間側の手作業。
- 音・読み上げは端末のスピーカー依存（Bluetoothスピーカー推奨）。iOSは最初の操作後に音が出る仕様。
